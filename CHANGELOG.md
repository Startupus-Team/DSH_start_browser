# Changelog — startapus-browser

## 0.19.1

### Исправлено

- **Размонтирование панели уничтожало сессию.** React перемонтирует панели (StrictMode,
  перемещение layout), а ядро — нет; из-за этого живые вкладки оставались без страницы
  (`sessions: []` при `panels: 2`). Теперь unmount только скрывает контейнер.
- Призраки убираются иначе: сессия, чья панель не смонтирована >2 мин, забывается
  (без освобождения lease — teardown у ядра); idle-GC 15 мин работает только для смонтированных.

  Пока управление у человека — кнопка меняется на «Вернуть агенту».
- **Блокировка агентских действий при перехвате:** `ui_act` и `ui_open` отвечают
  `E_HUMAN_CONTROL`, движок тоже отклоняет mutating-команды и не двигает страницу.
- `ui_status`/`/health` отдают `control` (`agent`/`human`) и `agentActive`.

### Проверки

- `ENGINE OK: 11/11` (E11: передача управления меняет состояние);
- `PASS CTRL-1: перехват управления человеком блокирует агента` (`selftest 44/44`).

## 0.18.2

### Исправлено

- **Периодическая уборка сносила живые страницы.** Свип каждые 60 с закрывал сессии с

  а не с активной сессией движка; если гость не готов — честный статус.
- Тест движка `E10`: навигация одной сессии не затрагивает другую (`ENGINE OK: 10/10`).

## 0.11.0 — архитектурный рефакторинг

### Изменено

- **Появился `client/engine.ts` — единственный владелец браузерного движка.** Он держит
  сессии `tabId → {<webview>, lease, url, title}` в собственных `fixed`-контейнерах в
  `document.body`, один long-poll канал к агенту и исполнение всех команд. Панель больше
  не создаёт гостя и не опрашивает канал.
- **`panel.tsx` — тонкий вид** (было 963 строки, стало ~300): chrome (иконки, адрес,
  копирование, внешний браузер, пикер), строка статуса и прямоугольник контента.
  Unmount вкладки лишь скрывает контейнер — страница и канал продолжают жить.
- Перемещение `<webview>` в DOM не используется: контейнер создаётся один раз и
  позиционируется по `getBoundingClientRect()` панели (ResizeObserver + scroll/resize).

### Удалено

- Из панели: boot/lease/attach/watchdog, per-panel poll-цикл, пер-панельная очередь,
  `sessionState`-восстановление, обработчики команд (перенесены в движок).

### Проверки

- `npm run build` — OK, `check-apply` PASS, `selftest` 45/45.
- Живая приёмка (4 вкладки, закрытие одной, `ui_select/act/capture`) — следующий шаг,
  см. `docs/architecture-v2.md` §6.

## 0.10.4

### Исправлено

- **Неактивные вкладки переставали работать.** Ядро сохраняет DOM вкладки только если
  флаг `keepMounted` объявлен **в самом типе вкладки**; я передавал его через
  `{ ...definition, keepMounted: true }`, и обёртка `try/catch` могла молча его отбросить.
  Теперь флаг в определении напрямую — переключение вкладок не размонтирует панель.
- Тик опроса обёрнут в `try/catch`: один сбой отчёта больше не останавливает цикл

- `/selftest` восстанавливает не только стор задач, но и маршрутизацию
  (`targetKey`, `targetPinned`, `clientKey`, реестр вкладок) — живой прогон диагностики
  больше не уводит цель на `startapus-browser`.
- `acquire` ограничен таймаутом 10 с: вместо вечного «подготовка guest…» будет ошибка.

## 0.10.3

### Исправлено

- **Пустые страницы во всех вкладках после закрытия одной.** Мой close-handler освобождал

## 0.8.1

### Исправлено

- **Плагин валил boot приложения** (`startapus-browser: failed`, «entry did not activate»):
  новый код управления вкладками читал `ctx.sidebarRight` без инъекции, а cordis бросает

  `apply()` не поднимает исключение. Включён в `npm run selftest` первым шагом.

## 0.1.0

### Добавлено

- Вкладка **Startapus Browser** в правой панели DSH (`sidebar.right.pane.tab`).
- Настоящий браузерный guest на Electron `<webview>` — без ограничений `<iframe>`
  (`X-Frame-Options`/CSP), с произвольными сайтами.
- Тулбар: назад, вперёд, обновить, адресная строка, кнопка выделения элемента.
- Пикер элемента `⌖`: подсветка под курсором, селектор в подсказке, `Esc` — отмена.
- Портрет выбранного элемента (селектор, тег, id/classes, размер, текст, URL).
- Вставка выбранного элемента агенту в композер как чип `ЭлементN` с
  модель-ориентированной сериализацией.
- Строка статуса панели: стадии `резервация → dom-ready → загрузка → загружено`,
  ошибки загрузки и падения guest-а видны без DevTools.

- Страница переживает переключение вкладок: `<webview>` хранится в модульном пуле,
  при уходе из панели элемент отцепляется, при возврате — переподключается
  (сохраняются скролл, введённые данные и история).
- Внизу панели только короткая строка статуса; полный портрет элемента в панель
  не печатается — он уходит агенту через чип.

### Технические решения

- DSH создаёт главное окно с `webviewTag: true`, поэтому `<webview>` доступен.
- Guest подключается только с резервацией из ядра: `window.dshDesktop.browser
  .acquire(workspace)` → `{ lease, partition }`; элемент получает `name=lease`,
  `partition`, `src=about:blank#<lease>` и `data-sidebar-browser-frame`.
- Ядро стирает `preferences` гостя перед attach, поэтому preload недоступен:
  пикер внедряется через `webview.executeJavaScript`.
- Пикер не возвращает значение напрямую (Electron не клонирует объект ошибки →
  `An object could not be cloned`), а паркует результат в `window.__startapusPick`;
  панель опрашивает простое значение.
- Lease одноразовый: при отсутствии `dom-ready` за 4 с панель освобождает
  резервацию и берёт новую.
- Клиентский бандл — CJS-фабрика внутри `window.__ModuleLoader__.load({ id, factory })`,
  как у штатных клиентских плагинов DSH.
- `peerDependencies` без пинов `@deepseek-ai/dsh-*`, иначе DSH блокирует плагин
  как несовместимый.

### Известные ограничения

- История и куки живут в partition `startapus-browser` (не общие с штатным браузером DSH).
- Загрузки файлов и всплывающие окна ограничены политикой ядра.
