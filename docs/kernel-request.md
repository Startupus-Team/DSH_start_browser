# Запрос к ядру DSH: активация вкладки из плагина

Составлено по живым наблюдениям 28.10 (startapus-browser, DSH 0.2.1-rc.3, Electron 44).

## Что происходит

*Плагин:* `startapus-browser` — сторонний тип вкладки правой панели (`ctx.sidebarRightTabs.register`).
Первый показ панели требует, чтобы ядро смонтировало и **активировало** вкладку, потому что гость
(`<webview>` с desktop lease) подключается только в видимом pane.

*Факты:*
1. `ctx.sidebarRight.openTab(kind, options)` создаёт вкладку, но не активирует её: панель
   монтируется в скрытом контейнере, в цепочке предков `div(0x0)`, `dom-ready` у `webview`
   не наступает (это подтверждено трассой DOM, которую движок пишет в `panelStatus`:
   `div(576x715) < div(576x782) < div(0x0) …`).
2. `ctx.sidebarRight.focus(tabId)` из контекста плагина не активирует вкладку (вызов
   не бросает, но видимость не меняется).
3. `tabId` известен плагину только после монтажа панели, то есть активация по `tabId`
   недоступна до того, как вкладка хоть раз показана.
4. В asar есть `shortcuts.register(...)` (каталог + обработчик), но нет `invoke`/`trigger`:
   программно вызвать свою же команду плагин не может.
5. Дом-клик по ярлыку вкладки из-под самой панели невозможен, пока панель не смонтирована
   в видимом месте: таймеры и `rAF` в скрытых панелях тротлятся, а собственный DOM-запрос
   из скрытого рендерера не находит ярлык (в логе `dom:tabs` приходит пустым/не приходит).

## Что нужно (минимальный API)

- `ctx.sidebarRight.openTab(kind, { activate: true })` — создать **и** активировать вкладку,
  как это делает клик пользователя по карточке guide.
- либо `ctx.sidebarRight.activate(tabId)` / `reuseOrCreate(kind)` для сторонних типов,
  вызываемый до монтажа панели.
- либо документированный способ вызвать зарегистрированную команду ярлыка
  (`shortcuts.invoke(id)`), чтобы плагин мог программно повторить жест пользователя.

## Почему это важно

Без этого любой сторонний тип вкладки с «живым» контентом (вебвью, видео, canvas,
терминал с нативным рендером) не может быть открыт агентом: агент создаёт вкладку,
которая никогда не становится видимой, и контент не инициализируется. Пользователь
вынужден каждый раз открывать вкладку вручную, что ломает основной сценарий
«агент делает всё сам».

## Обходной путь в плагине (текущий)

- Вкладка открывается человеком (`⌘T` — команда `startapus-browser.new`), ядро её
  активирует, панель смонтирована видимой и реконсиляция создаёт гостя.
- Если панель всё же смонтирована скрытой — движок не жжёт `acquire`, показывает
  статус «вкладка скрыта: страница создастся, когда её покажут» и создаёт гостя
  в тот момент, когда вкладка становится видимой (реконсиляция раз в 500 мс).
