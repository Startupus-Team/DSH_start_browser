## 3. Честная оценка

**Сильная сторона.** Контракт инструментов теперь однородный и машинно-проверяемый: 25 инструментов,
единая схема, единый рендер, пять офлайн-гейтов (`SCRIPT · RULES · ENGINE · IMPORTS · apply · TOOLS · selftest 43/43`).
Класс дефектов «параметр не на том инструменте» и «импорт несуществующего экспорта» закрыт тестами.

**Слабая сторона.** Живая проверка отстаёт от кода: после серии правок (visibility-активация,
зомби-гард, синхронный `read_page`, `ref`, baseline) вживую проверены только те инструменты,
что не затрагивались. Панель дважды падала в рантайме (`showSession is not defined`), и это
не ловилось ни сборкой, ни `/health` — только скриншотом.

**Главный риск по инструментам.** `ui_read_page`, `ui_act`, `ui_screenshot` — три самых
полезных для агента — пока не подтверждены вживую в текущей сборке; их контракты
изменились сильнее всего.

## 4. Что доработать (по инструментам)

1. **Живой прогон после рестарта**: `ui_read_page` → `ui_act {ref}` → `ui_screenshot {selector}` →
   переключение вкладок → 7 сессий → закрытие крестиком. Это 5 пунктов, которые закроют ⏳.
2. **`ui_guest_state` и `ui_screenshot`**: параметр `tabId`, чтобы работать с неактивной сессией.
3. **`ui_console`**: лимит 200 строк и пагинация (как у Claude).
4. **`ui_evidence`**: отдавать те же 48 свойств + pseudo/ancestors, что у человека при пике.
5. **Не хватает инструментов из эталона**: `get_page_text` (article-first), сеть
   (`PerformanceObserver`), `ui_inspect {styles:[...]}`.
6. **Типизированные отказы**: сейчас `E_*` строкой; нужен машинный код + hint/retryable.
