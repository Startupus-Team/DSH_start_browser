# Браузер Startapus: стандарты и ТЗ (v1)

Документ обязателен для любых изменений `startapus-browser`. Аудит и обоснование —
[`architecture-audit.md`](architecture-audit.md).

## Часть I. Стандарты (нарушение = блокирующий дефект)

**S1. Владелец раскладки — ядро.** Плагин не вычисляет «видимо/невидимо» по геометрии.
`visible` берётся только из `props.visible` вкладки (ядро). Запрещены опросы
`getBoundingClientRect` по предкам для решения о скрытии.

**S2. Guest привязан к монтированию панели, а не к видимости.** Пока панель смонтирована —
существует ровно один guest. Скрытие/показ вкладки не создаёт и не уничтожает guest вручную;
это делает ядро.

**S3. Один guest = один lease = один `about:blank#<lease>`.** Повторный attach одного и того же
lease запрещён контрактом ядра. Пересоздание guest = новый `acquire`; освобождение — ровно один
`release` на lease, идемпотентно.

**S4. Никаких `display:none`/`visibility:hidden` на контейнере живого guest.** Показ/скрытие
делает ядро. Наш стиль может управлять только внутренними оверлеями (баннеры, заглушки).

**S5. Запрещён «второй движок состояний».** Никаких периодических reconcile-циклов, которые
самостоятельно создают/пересоздают guest. Разрешены: реакция на события webview, смена
`props.visible`, действия человека/агента.

**S6. Явная машина состояний.** Каждая вкладка обязана находиться в одном из состояний:
`new → mounting → loading → ready | failed | restore`. Переходы только по событиям; UI обязан
показывать `loading` (заглушка), `failed` (причина + «Повторить»), `restore` (последний адрес).

**S7. Один адрес — один источник истины.** Адресная строка показывает `element.getURL()` после
`did-navigate*`; до первой навигации — `requested` (то, что ввёл человек/агент). Запись
`initialUrl` в состояние после первого монтирования запрещена.

**S8. Ревизии команд.** Навигации/перезагрузки нумеруются (`revision`); ошибки и результаты
старых ревизий игнорируются. Один пользовательский жест = максимум одна навигация.

**S9. Checkpoint переживает перемонтирование.** Последний адрес (и заголовок) хранятся вне
React-дерева (module store + `sessionStorage`) и восстанавливаются при новом монтировании.

**S10. Ошибки не молчат.** `did-fail-load` (кроме `-3`), `render-process-gone`, `destroyed`
обязаны давать видимое состояние + запись в журнал `~/.dsh/startapus-host.log`.

**S11. Наблюдаемость.** Обязательные события: `guest:create`, `guest:attach`, `guest:dom-ready`,
`guest:navigate`, `guest:fail`, `guest:release`, `pane:mount`, `pane:unmount`, `cmd:route`
(какой инстанс получил команду). Без них изменение не принимается.

**S12. Один инстанс-владелец на окно.** Команды агента адресуются конкретной вкладке
(`tabId`), а не «активному инстансу». Статус/URL в health отдаёт владелец окна; остальные
инстансы не перезаписывают поля.

**S13. Тесты обязательны.** Любой фикс мигания/жизненного цикла закрывается тестом в
`check-engine`/`check-scripts` с воспроизведением: до фикса тест падает.

**S14. Партиции и сессии.** Плагин не управляет партицией; требование persist-партиции —
в [`kernel-request.md`](kernel-request.md). Внутри одного запуска используется один
workspace-ключ на все вкладки.

## Часть II. Целевая архитектура

```
host (src/index.ts)
  └─ команды агента (tabId-scoped) ──► очередь :: transport
client (одна панель = одна вкладка)
  ├─ store (module, один на окно)         // sessions, checkpoints, ownership
  ├─ tabMachine (new→mounting→loading→ready|failed|restore)
  ├─ guestFactory (acquire → element → append → release)
  └─ UI: toolbar + placeholder/failed/restore + guest host
```

Правила границ:

- `guestFactory` — единственное место вызова `acquire/release` и `appendChild`;
- `tabMachine` — единственное место переходов состояния;
- UI читает store, не пишет в него напрямую;
- host не знает про DOM, только `tabId`.

## Часть III. ТЗ (что должно быть сделано)

### Функциональные требования

- **FR1** При открытии вкладки: `loading`-заглушка ≤ 50 мс, затем либо страница, либо `failed`.
- **FR2** Переключение вкладок не вызывает `acquire/release` и не перезагружает страницу
  (guest остаётся прикреплённым; ядро само управляет показом).
- **FR3** Ввод адреса: ровно одна навигация; при ошибке — `failed` с кодом и «Повторить».
- **FR4** Возврат на вкладку после сбоя восстанавливает checkpoint-адрес.
- **FR5** Команды агента выполняются на указанной вкладке; при отсутствии вкладки — ошибка
  `E_NOT_FOUND`, а не действие на «активной».
- **FR6** Никаких «миганий»: за 10 минут простоя вкладки — 0 изменений `display`, 0 навигаций,
  0 acquire/release.

### Нефункциональные требования

- **NFR1** Idle CPU панели < 1% (сейчас 700 мс таймер удалён; в плане — удалить reconcile).
- **NFR2** Память: не более одного guest на вкладку; при лимите — LRU с явным `release`.
- **NFR3** Время восстановления после `render-process-gone` ≤ 2 с до `failed`-состояния
  (без автоматических перезагрузок).
- **NFR4** Все события S11 — в журнале с `tabId`.

### Приёмка (AC)

| ID | Проверка | Критерий |
|---|---|---|
| AC-1 | 30 циклов переключения вкладок | 0 лишних навигаций, 0 acquire |
| AC-2 | 10 мин простоя | 0 событий `guest:navigate`, 0 `pane:visible` флапов |
| AC-3 | Ошибка сервера (500/refused) | состояние `failed`, баннер с причиной и «Повторить» |
| AC-4 | Возврат после снятия панели | checkpoint-адрес загружается сам |
| AC-5 | Команда агента с `tabId` | выполнена на этой вкладке; health подтверждает |
| AC-6 | `revMatch` | у всех панелей один `clientRev` (после перезапуска) |
| AC-7 | Полный прогон | `GATE OK`, `ENGINE OK`, `SCRIPT OK` |

### План работ

| Фаза | Содержание | Файлы |

## Часть IV. Метрики стабильности (для приёмки релиза)

- `acquires/releases` за час простоя: 0;
- навигаций на одно действие пользователя: ≤ 1;
- `pane:visible` флапов за 10 минут: 0;
- время до первого рендера после открытия вкладки: ≤ 800 мс (локально);
- доля сессий с `revMatch: true` после перезапуска: 100%.
