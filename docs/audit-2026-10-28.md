## Открытые проблемы (по убыванию риска)

### ~~H1. Нет автотестов на клиентский движок~~ — ИСПРАВЛЕНО (F6)
`selftest` покрывает host (39 проверок), `check-apply` — только активацию плагина.
Логика движка (сессии, лимиты, навигация, снимок) тестами не покрыта, поэтому такие
регрессии, как «гость вне DOM», «двойная навигация», «сессия не закрывается», ловятся
только живым прогоном.
**Рекомендация:** вынести чистые функции (политика URL, LRU-выбор сессии, вычисление кропа)
в отдельный модуль и покрыть их в `selftest` без DOM.

### ~~H2. `verify` перезагружает страницу~~ — ИСПРАВЛЕНО (F5)
`engine.ts` (ветка `verify`): `view.reload()` + пауза 1500 мс перед замером.
Это требование FR-11 (детерминизм), но побочный эффект — во время ревью у пользователя
сбрасывается страница/скролл, прерываются загрузки и введённые формы.
**Рекомендация:** по умолчанию settle-only (шрифты + 2 кадра), `reload` — опция
`ui_verify { reload: true }`, и фиксировать это в ТЗ.

### ~~H3. Кроп на canvas может считать не тот масштаб~~ — ИСПРАВЛЕНО (F7)
`engine.ts: cropDataUrl()` берёт `activeGuest()` вместо гостя, чей снимок кропится.
Если пользователь переключит вкладку между `capturePage` и кропом, `ratio` посчитается
по чужому `innerWidth`.
**Рекомендация:** передавать guest в `cropDataUrl` явно.

### ~~H4. Evidence глобальный~~ — ИСПРАВЛЕНО (F8)
`index.ts`: `lastEvidence` один на host. При нескольких вкладках задача может быть создана
по evidence предыдущей страницы (`task_create` → `E_NO_PICK` или неверный локатор).
**Рекомендация:** `lastEvidence` в разрезе `tabId` + `ui_status.evidenceTab`.

### H5. `hasGuest`/`url` в `/health` отражают последнюю отчитавшуюся вкладку — СРЕДНИЙ
Честные данные — `sessions[]`; поля-зеркала могут отставать. Инструменты (`ui_guest_state`,
`ui_select`, `ui_act`) работают с **активной** сессией движка, но параметра `tab` нет.
**Рекомендация:** добавить `tabId?` в агентские инструменты или явно документировать.

### ~~H6. Rate-limit не покрывает новые инструменты~~ — ИСПРАВЛЕНО (F9)
`index.ts`: лимиты 30/20 в минуту заданы для старого набора; `ui_new_tab`, `ui_close_tab`,
`ui_read_page`, `ui_act` могут вызываться в цикле и плодить сессии/команды.
**Рекомендация:** общий family-лимит на «управляющие» инструменты + лимит на `ui_new_tab`.

### ~~H7. Маршруты `/client/*` не проверяют клиента~~ — ИСПРАВЛЕНО (F10)
Любой процесс/страница на localhost, знающая порт, может отправлять события панели
(подменить `url`, `evidence`). Для десктопного локального сценария риск умеренный,
но токен у рендерера уже есть (`window.dsh.getAuthToken()`), проверка стоит одну строку.

### ~~H8. Молчаливое вытеснение сессии~~ — ИСПРАВЛЕНО (F11)
При `MAX_SESSIONS = 6` LRU-сессия закрывается без уведомления: вкладка останется, страница
перезагрузится при возврате. **Рекомендация:** статус/бейдж «страница выгружена».

### ~~H9. Мусор в профиле~~ — ИСПРАВЛЕНО (F12)
`~/.dsh/startapus-crops/` накопил 47 файлов без ротации. **Рекомендация:** держать N последних.

### H10. Документация расходится с кодом — НИЗКИЙ
`startapus-browser-compliance.md` частично описывает прежнюю архитектуру (per-tab routing),
`ui_close_tab` в ТЗ значится как закрытие вкладки, а закрывает сессию движка.

### H11. Зависимость от приватных API ядра — РИСК ОБНОВЛЕНИЙ
Используются `ctx.get('sidebarRight')`, `registerCloseHandler`, `keepMounted`,
`dshDesktop.browser.acquire`. Они описаны в README ядра, но не являются стабильным
публичным контрактом. **Рекомендация:** зафиксировать проверку версии DSH при активации
и мягкую деградацию (уже есть для `keepMounted`/close-handler, нужна для `openTab`).
