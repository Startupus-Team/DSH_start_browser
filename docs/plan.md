## Фаза 1 — стабильность жизненного цикла (1–2 дня)

1. `destroyed` / `render-process-gone` на госте → пересоздание сессии и повторная резервация lease.
2. `verify` привязать к выданной команде (`commandId`, nonce) — сейчас результат принимается без сверки.
3. Атомарная запись стора задач (tmp + rename), восстановление после обрыва.
4. Long-poll вместо опроса раз в 2.5 с; мьютекс на тик (сейчас тики могут накладываться).
5. Проверка `buildRev`/`capabilities` при подключении клиента к host.

Приёмка: сценарий «убить рендерер панели» → канал восстанавливается, страница возвращается; `queued` не растёт.

## Фаза 2 — контракты инструментов (1–2 дня)

1. `tabId` в `ui_guest_state`, `ui_screenshot`, `ui_evidence` — работа с неактивной сессией.
2. `ui_console`: 200 строк + пагинация; `ui_evidence`: паритет с пикером (48 свойств, pseudo/ancestors, `0px`).
3. `get_page_text` (article-first) и сетевой инструмент на `PerformanceObserver`.
4. Типизированные отказы `{ code, retryable, hint }` вместо строк.
5. `ui_inspect { selector, styles[] }` — точечный замер как `preview_inspect` у Claude.

Приёмка: `TOOLS OK` + живой прогон каждого нового инструмента.

## Фаза 3 — безопасность (1–2 дня)

1. Untrusted-конверт для всех page-derived полей (console, read_page, find, guest_state, действия).
2. Пикер: результат не через `window.__startapusPick`, а через изолированный канал.
3. Токен рендерера на `/client/*`; `POST` + токен для `/panic|/selftest`; снять CORS `*`,
   убрать `sessions` из `/health`.
4. `E_GUEST_GONE` вместо тихой потери команд.

Приёмка: `curl` без токена → 401/403 на всех изменяющих маршрутах; page-derived данные помечены.

## Фаза 4 — процесс и документация (0.5 дня)

1. `npm run live` — обязательный гейт перед «готово»; теги состояния в git на каждый прогон.
2. Матрица соответствия обновляется тем же коммитом, что и код.
3. Регламент релиза: версия в `package.json` = тег; CHANGELOG по фичам, не по файлам.
