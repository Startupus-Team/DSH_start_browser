# План v3: от «работает в теории» до приёмки и релиза

Составлен 28.10 после разбора архитектурных дефектов (см. `docs/architecture-v3.md`,
`docs/kernel-request.md`). Основание: живая эксплуатация выявила 4 класса дефектов —
одноразовое решение о создании гостя, утечка/лавина lease, подмена вкладки в адресной
строке, отсутствие в ядре API активации вкладки из плагина.

## Фаза A — живая приёмка (сейчас, блокирует всё)

**Цель:** доказать на открытой человеком вкладке, что контракты работают.

| # | Проверка | Критерий |
|---|---|---|
| A1 | Человек открыл вкладку `⌘T`, клиент актуальный | `/health.clientRev == buildRev`, `revMatch: true` |
| A2 | Гость создан и страница держится | `sessionsCount ≥ 1`, `urlHost` есть, `crashes 0`, `recoveries 0` |
| A3 | Нет лишних навигаций при работе агента | до/после серии команд `navigations` не растёт, `loadErrors 0` |
| A4 | Инструменты вживую | `ui_read_page` (trust-конверт) → `ui_act{ref}` → `ui_screenshot{selector}` → `ui_page_text` → `ui_network` → `ui_inspect` → `ui_console` (200) → `ui_focus_tab` |
| A5 | AC-1 | `task_create → triaged → ui_verify → verified`, в вердикте `baseline` и `observed` |
| A6 | Адресная строка в своей вкладке | ввод адреса меняет URL **этой** вкладки, `lastNavAttempt.ok: true` |

Закрытие фазы: все A1–A6 подтверждены в одном прогоне, отчёт в матрицу.

## Фаза B — активация вкладки агентом (зависит от ядра)

**Цель:** агент открывает вкладку сам, без жеста человека.

- B1: `docs/kernel-request.md` отправлен владельцу DSH как запрос фичи.
- B2: если в ядре появится `openTab({activate:true})` / `activate(tabId)` / `shortcuts.invoke(id)`
  — подключить в `requestOpenTab()` и снять ограничение «первую вкладку открывает человек».
- B3: до появления API — канонический вход `⌘T`, в интерфейсе статус прямо просит нажать.
- B4 (локальный резерв): если активация из плагина невозможна, но вкладка создана скрытой —
  `setPaneState` получает `visible` позже, реконсиляция создаёт гостя без перезагрузки страницы.

**Критерий:** из состояния «ни одной вкладки» `ui_new_tab` приводит к `sessionsCount ≥ 1`
без участия человека.

## Риски и как снимаем

| Риск | Митигация |
|---|---|
| Кернел не даст активацию вкладки из плагина | документированный запрос + канонический `⌘T`; вкладка живёт, когда открыта человеком |
| Скрытые панели не подключают webview | реконсиляция по видимости; скрытая вкладка не жжёт `acquire` |
| Падение рендерера на тяжёлых сайтах | закрытие вкладки по контракту ядра + `counters.crashes` в гейте `live` |
| Рассинхрон клиента и host | `clientRev`/`revMatch` в `/health`, `npm run live` падает при рассинхроне |
| Накопление cookie DSH | `scripts/dsh-cookie-doctor.mjs`, минимизируем рестарты |
