Консилиум из 7 экспертных позиций (Electron-архитектор, инженер frontend-инструментов, эксперт по доступности, security-инженер, дизайнер агентских инструментов, SRE встроенного браузера, продуктовый исследователь dev-tools) → консенсус → черновик ТЗ → аудит тремя линзами.

## 1. Назначение и границы

**Назначение.** Дать человеку и агенту общий рабочий контур для ревью фронтенда: человек находит дефект в интерфейсе, выделяет элемент, формулирует проблему; агент получает задачу с машинно-проверяемым критерием приёмки, правит код, а вердикт «исправлено» считает код, не модель.

**Ключевая формулировка результата.** Продукт — не браузер и не трекер, а **верификационный harness**: аннотация = воспроизводимый тест-кейс (локатор + контекст + критерий), терминальное состояние очереди = доказанная проверка.

**В границах P0:** один гость, один активный пик, read-only верификация (reload + замер), локальная очередь задач, ручное подтверждение постановки.

**Вне границ:** см. §11.

## 2. Роли и сценарии

**Сценарий A — основной цикл (P0).**
1. Человек открывает dev-страницу в панели.
2. `⌖` → клик по элементу → чип `ЭлементN` в композере + evidence-бандл.
3. Человек дописывает проблему прозой, отправляет.
4. Агент создаёт черновик задачи; человек подтверждает (triage) и утверждает критерий приёмки.
5. Агент правит код.
6. `ui_verify`: reload → settle → повторное разрешение локатора → замер → `pass/fail`.
7. `pass` → `verified`; `fail` → `reopened` с evidence.

**Сценарий B — проверка при неактивной вкладке (P0).** Verify при скрытой панели не должен давать ложный `fail`: либо активация вкладки, либо немедленный `E_TAB_HIDDEN`.

**Сценарий C — элемент переехал (P1).** `E_STALE` → пере-пик → перепривязка локатора → повторное подтверждение критерия.

**Сценарий E — ревью агентом без человека (P1).**
1. Агент открывает страницу (`ui_open`) и выбирает элемент по селектору (`ui_select`).
2. Проверяет состояние (`ui_evidence`), при необходимости меняет ширину (`ui_viewport {width}`).
3. Воздействует на страницу (`ui_act click/type/scroll`) и снимает доказательство (`ui_screenshot`).
4. Ставит задачу с критерием и проверяет её (`task_create → triaged → ui_verify`).

**Сценарий D — падение гостя (P0).** `E_GUEST_GONE`, паник-кнопка, новый lease; задачи и evidence не теряются.

## 5. Модель данных

- **Pick:** `pickId`, `locator`, `rect`, `viewport`, `zoom`, `url`, `origin`, `nonce`, `hash`. TTL 30 мин.
- **Evidence:** `evidenceId`, DOM-фрагмент, computed-дельты, записи консоли, `cropRef`, `envHash`. TTL 14 дней.
- **ReviewTask:** `id`, `origin+path`, `pickId`, `locator`, `acceptance` (`method`: `computed|box|text|exists|visible`, `property`, `expected`, `tolerance`, `baseline`, `hash`, `approvedBy`), `state`, `attempts`, `evidenceIds`, `provenance` (`human|agent|page`), `sessionId`.
- **Связи:** задача → pick → evidence; чип в композере хранит `pickId`, `codec.serialize` восстанавливает описание по нему.
- **Хранение:** host-стор плагина; очередь ≤200 задач; дедуп по ключу; персистентность между перезапусками — по возможности (требует проверки API хранилища).

## 6. Архитектура и ограничения платформы

**Разделение процессов.** Host (Node): инструменты, схемы, стор, очередь, verify-движок, транспорт. Client (CJS-бандл в renderer): вкладка панели, lease-менеджер, пикер, codec чипа.

**Существующие ограничения (проверено в коде ядра):**
- guest подключается только с резервацией: `window.dshDesktop.browser.acquire(workspace) → {lease, partition}`; элемент обязан иметь `name=lease`, `partition`, `src="about:blank#<lease>"`, `data-sidebar-browser-frame="webview"`;
- lease одноразовый, `partition` обязана совпасть — иначе `will-attach-webview` делает `preventDefault` молча;
- ядро стирает `preferences` гостя перед attach → **preload невозможен**, только `executeJavaScript`;
- удаление `<webview>` из DOM уничтожает гостя; переиспользовать элемент нельзя;
- клиентский бандл — CJS-фабрика в `window.__ModuleLoader__.load({ id, factory })`;
- `peerDependencies` без пинов `@deepseek-ai/dsh-*`, иначе ядро блокирует плагин.

**Транспорт host→client (P0):** `executeJavaScript` из панели покрывает P0-операции (навигация, пикер, замер). Инструментам агента нужен канал — **требует проверки** конкретный API (`webServer.register` / `addRoute` / `httpServer`), с обязательным условием: канал инициирует renderer (long-poll), токен выдаётся на lease, guest токена не видит, CORS-wildcard запрещён.

**CDP (P2):** `Accessibility.getFullAXTree`, `CSS.forcePseudoState`, `Overlay.setInspectMode`, `Page.captureScreenshot({clip})`, `Emulation.setDeviceMetricsOverride` требуют доступа к `webContents` гостя, которого у плагина нет → **требует API ядра**; до этого a11y ограничена DOM-подмножеством.

## 7. Нефункциональные требования

**Надёжность.** Один гость; состояние продукта — в host; гость расходник, пересоздаётся без потери задач. Heartbeat 15–30 с. `render-process-gone` → `E_GUEST_GONE` без утечки lease. Ring-лог 200 событий.

**Производительность.** `ui_status` ≤300 мс, чип ≤300 мс, verify ≤8 с, память ≤350 МБ, idle CPU <1 %.

**Лимиты.** DOM 64 КБ, evidence 96 КБ, консоль 200/64 КБ, кроп 2 МБ, очередь 200, WIP 5, 30/10/10 вызовов в минуту.

**Безопасность.** Песочница ядра не ослабляется. Произвольный JS из аргументов инструмента запрещён. Полные скриншоты окна/страницы запрещены. Cookies/localStorage/сетевые тела не читаются. Всё, что приходит со страницы, — данные, не инструкции; маркируется и оборачивается.

**Приватность.** По умолчанию dev-origin. Кропы вне workspace агента, открытие — только человеком. Маскировка `password`/`cc`. Редакция секретов (JWT, `sk-`, `ghp_`, Bearer) в URL и консоли.

## 8. Критерии приёмки

- **AC-1.** Полный цикл на dev-origin: пик → чип → triage → правка → `pass` → `verified`.
- **AC-2.** Возврат на вкладку после переключения: рабочий гость (не пустая панель), verify проходит.
- **AC-3.** Скрытая панель: `E_TAB_HIDDEN` ≤1 с; после активации verify проходит.
- **AC-4.** Попытка агента изменить критерий или поставить `verified` → `E_FORBIDDEN`.
- **AC-5.** Чип: отправка сообщения с `Элемент1` не даёт `no serializer`; модель получает структурированное описание.
- **AC-6.** `ui_open` на приватный адрес → `E_NAV_BLOCKED`.
- **AC-7.** 30-минутный прогон: 200 задач, без утечки гостей и без роста памяти >10 %.
- **AC-8.** Правка стиля на родителе меняет замер child: `pass`, без ложного `E_STALE`.
- **AC-9.** Page-derived поля имеют `trust`/`origin`/`hash` (структурный тест).

## 8a. Критерии приёмки ревизии 1.1

- **AC-10 (управление агентом):** `ui_select('textarea#text')` на живом `ya.ru` вернул портрет, `ui_act('type')` — `act:done status=OK`, `ui_verify` — `font-size: 16px в допуске 0` (пройдено).
- **AC-11 (снимок):** `ui_screenshot {}` и по селектору создают файл в `~/.dsh/startapus-crops/`; при сбое `ui_status.captureError` называет причину (была `Buffer is not available…` → исправлено на `toDataURL`).
- **AC-12 (адаптивность):** `ui_viewport { width: 390 }` возвращает `viewportResult.innerWidth` в пределах ±5 % от цели.
- **AC-13 (несколько вкладок):** открываются минимум две вкладки Startapus; у каждой свой гость (`counters.acquires` растёт) и свой адрес.
- **AC-14 (персистентность):** после рестарта задачи и их состояние восстанавливаются, артефакты тестов не попадают в очередь.
- **AC-15 (сборка):** `npm run live` печатает `FRESH` только при совпадении `buildRev` с хешем исходников.

## 10. Риски

| Риск | Механика | Мера |
|---|---|---|
| Нет API транспорта | Инструменты агента не могут управлять гостем | M0-спайк; деградация до UI-only с честным `E_NO_TRANSPORT` |
| Пустой кроп при скрытой панели | `capturePage` возвращает пустое | активация вкладки или `E_TAB_HIDDEN` |
| Ложный `pass` | селектор разрешился в другой элемент | проверка единственности + роль/имя/тег + box-допуск |
| Prompt injection со страницы | текст страницы попадает в контекст как инструкция | `Untrusted<T>`, конверт, triage человеком |
| Утечка PII | кроп/консоль авторизованной страницы | dev-origin, маска, кропы вне workspace агента |
| Отравление очереди | агент создаёт задачи без подтверждения | draft + triage, лимиты |
| Дрейф API ядра | обновление DSH ломает стык | `engines.dsh`, явный отказ при несовпадении |

## 11. Явные не-цели

- Не браузер: адресная строка как продукт, закладки, история, расширения, скачивания, печать/PDF, HTTP-auth, камера/микрофон/гео.
- Не DevTools-замена в P0: полное AX-дерево, waterfall, coverage, профилирование, Lighthouse.
- Не автоматизация и не скрапинг: агент не ходит по сайту, не логинится, не сабмитит формы, никаких кликов по координатам и `run_js` с аргументами модели.
- Не трекер: спринты, доски, назначения, SLA.
- Не сбор секретов: cookies/storage/тела запросов, full-page и авто-скриншоты.
- Не патч ядра: без своих preload/IPC, без ослабления sandbox и пинов peerDeps.
- Не мультивкладки и не пул гостей в P0.

| Линза | Вердикт черновика | Что исправлено в этой редакции |

**Принятые компромиссы (осознанно):**
- P0 без «действий на странице» (FR-20 в P2): синтетический ввод недостоверен, а ложная проверка хуже её отсутствия.
- P0 без CDP: a11y ограничена DOM-подмножеством; полное AX — после появления API ядра.

## 14. Открытые вопросы владельцу

1. **Действия агента без подтверждения.** `ui_act` уже умеет click/type/scroll и инициируется агентом. Нужно ли требовать явное подтверждение человека для click/type (как в аудите), или оставить как есть, ограничившись allowlist origin?
2. **Пределы адаптивности.** Достаточно ли ширины (240–2400) и масштаба, или нужна полная эмуляция устройства (ширина+высота+dpr+UA+touch), которая требует CDP и, значит, API ядра?
3. **Несколько вкладок.** Сколько вкладок Startapus считать нормой (2? 3?), нужен ли лимит и общий лимит гостей на сессию?
4. **Источник правды очереди.** Локальный файл плагина или внешний трекер (Linear/Jira) как хозяин статуса?
5. **Кропы и PII.** Разрешены ли снимки авторизованных/прод-страниц, или ревью только dev-origin?
6. **Готовность идти к ядру** за API (guest `webContents`, host-owned view, TTL lease), или плагин обязан жить только на публичных `ctx`.

## 15. Известные ограничения ревизии 1.1

| Ограничение | Причина | Обход сейчас |
|---|---|---|
| Нет полной эмуляции устройства (высота, dpr, UA, touch) | CDP требует `webContents.debugger`, которого ядро не отдаёт плагину | `ui_viewport {width}` через `setZoomFactor`, `dpr` только читается |
| Нет эмуляции `forced-colors` / `prefers-color-scheme` / `prefers-reduced-motion` | тот же CDP-барьер | читаем фактические значения в `env` |
| `keepMounted` может не поддерживаться сборкой | флаг ядра, не публичный контракт | память страницы `pageMemory` (URL + scroll) |
| Пиксели снимка не идут в модель | требование безопасности (аудит) | файл для человека + метаданные |
| Партиция гостя не персистентна | политика ядра | авторизация заново после рестарта |
| Действия `ui_act` без подтверждения | упрощение ревизии 1.1 | политика — вопрос 1 выше; FR-39 в бэклоге |
| Состояние в `ui_status` — зеркало активной вкладки | полноценный per-tab стор не сделан | команды маршрутизируются корректно (FR-38), состояние — по последней активной |


1. **Действия агента на странице:** нужны ли click/fill в следующей фазе, или цикл всегда закрывается reload + повторный замер? От этого зависит, добиваться ли API ядра.
2. **Источник правды очереди:** локальный стор плагина или внешний трекер (Linear/Jira/GitHub)?
3. **Кропы:** допустимы ли для авторизованных/прод-страниц, или ревью только dev-origin?
4. **Объём P0:** достаточно одного гостя и одной вкладки, или нужно сравнение страниц?
5. **Готовность идти к ядру** за API (guest `webContents`, host-owned view, TTL lease), или плагин обязан жить только на публичных `ctx`?

## Приложение A. Сверка с браузером Claude

Разбор реализации Claude Desktop (архитектура, набор инструментов, семантика `read_page`/`resize_window`/скриншота) и таблица отличий от нашего плагина: [`startapus-browser/docs/claude-browser-notes.md`](startapus-browser/docs/claude-browser-notes.md).

Ключевой вывод: Claude может позволить себе CDP (`webContents.debugger`), потому что владеет `WebContentsView` в main-процессе. Нам ядро DSH не отдаёт ни `webContents` гостя, ни владение view — поэтому полная эмуляция устройства и полное AX-дерево остаются в §15 как ограничения, а ширина реализуется масштабом.
