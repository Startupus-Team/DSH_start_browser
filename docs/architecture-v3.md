# Архитектура v3: управление жизненным циклом гостя

## Почему v2 не выдержала эксплуатацию

Жизненный цикл гостя был набором **событийных реакций**:

- панель смонтировалась → создать гостя;
- `props.visible` изменился → показать/скрыть;
- `destroyed` → пересоздать;
- адресная строка → `loadURL`.

Каждая реакция принимала решение по **одному снимку** состояния. Отсюда три класса
дефектов, которые мы ловили вживую:

1. Панель смонтирована скрытой (`ancestor 0x0`) → `acquire` есть, `dom-ready` нет,
   `attachFailures` растёт, а после показа никто не пересоздаёт гостя.
2. `render-process-gone` → пересоздание на мёртвом lease → цикл: `acquires 214`,
   `recoveries 213`, панель мигает.
3. Адресная строка ходила через `activeGuest()` — иногда в **чужую** вкладку, а потом
   писала «гость этой вкладки не создан» для своей.

## v3: желаемое состояние + реконсиляция

```
panel ──setPaneState(tabId, {url, host, visible})──► engine.paneState
                                                           │
                            reconcile() каждые 500 мс, при setPaneState,
                            visibilitychange, focus
                                                           ▼
   для каждой вкладки: visible && нет живого гостя → создать (acquire→webview→dom-ready)
                       visible && гость есть         → показать
                       !visible                      → скрыть, НЕ создавать
```

Правила-инварианты:

1. **Гость создаётся только для видимой панели.** Скрытая вкладка не жжёт `acquire`
   и не копит `attachFailures`. Видимость проверяется по всей цепочке предков (`0x0`
   или `display:none` у любого = скрыто), а не только по своему `div`.
2. **Один входной канал состояния** — `setPaneState`. Панель больше не «командует»
   созданием напрямую.
3. **Адрес — приоритетнее дефолта.** `openInSession` пишет `requestedUrl`; при создании
   гостя этот адрес побеждает `startUrl` и открывается на `dom-ready` (никаких
   `loadURL` до `dom-ready`).
4. **Адресная строка строго в своей вкладке:** никакого `activeGuest()`-фолбэка.
5. **Падение рендерера = закрытие вкладки** (контракт ядра), lease освобождается сразу.
6. **Пересоздание (`destroyed`) ограничено** предохранителем: 3 падения за 10 с →
   `E_GUEST_LOOP`, стоп. Ledger живёт на вкладку, а не на объект сессии.
7. **Один lease = одна сессия:** `releaseLease()` на закрытии, падении, зомби.

## Диагностика (чтобы не гадать)

- `note()` в транспорте → `~/.dsh/startapus-host.log`: `lease:acquire`, `lease:release`,
  `guest:lost` (с reason), `guest:crashed`, `attach:timeout` (+ трасса DOM), `dom:tabs`.
- `/health`: `panelMounts`, `counters {acquires, releases, recoveries, crashes,
  navigations, loadErrors, attachFailures}`, `lastLoadError`, `revMatch`, `shortcutState`.
- Трасса DOM при отказе `attach` пишется прямо в `panelStatus` — видно без рестарта host.

## Тесты инвариантов (`scripts/check-engine.mjs`)

`E13` падение рендерера закрывает вкладку · `E14` навигация до `dom-ready` откладывается ·
`E15` команда ждёт готовности гостя · `E16` одно падение → одно восстановление и release ·
`E17` серия падений останавливается · `E18` скрытая панель не получает гостя, видимая
получает · `E19` адрес, введённый до создания гостя, открывается после его создания.
