# ADR-001: решения владельца по консилиуму

Дата: 28.10. Контекст: консилиум (`docs/council-consensus.md`) вынес P0-вопросы,
владелец дал прямые ответы. Здесь фиксируются решения и их последствия.

## Решения

1. **Действия агента — автопилот.** Подтверждение человека на каждый `click`/`type` **не вводим**.
   Claude делает наоборот (approval на каждое действие), но наш сценарий — личный
   дизайн-ревью-инструмент под собственным контролем.
   - Следствие: P0-A из консилиума снимается как требование, риск принимается.
   - Компенсация (не отменяется): URL-политика (http(s), запрет приватных адресов),
     rate-limit на управляющие инструменты, untrusted-конверт данных страницы.
2. **Критерий приёмки утверждает агент.** Экрана «человек утверждает критерий» не делаем.
   - Следствие: P0-E снимается; ответственность за критерий — на агенте и на ревьюере.
3. **Верификация: на усмотрение архитектора.** Принято решение:
   - при создании задачи фиксируется **baseline** — фактическое значение свойства из evidence
     (`task.baseline`), плюс флаг `baselineMatched`, если критерий уже выполнялся;
   - вердикт хранит `baseline → observed` и `reason` (`task.lastObserved/lastReason`),
     они видны агенту в `task_get`;
   - тавтология «expected = observed, потому что модель так захотела» больше не скрыта:
     `baselineMatched: true` показывает, что чинить было нечего.
4. **Приоритет — стабильность и архитектурная правильность, не скорость.**
   - Следствие: каждое изменение проходит офлайн-гейты (`SCRIPT · RULES · ENGINE · apply · selftest`),
     живой прогон — отдельный контроль после рестарта; «зелёный» selftest не считается
     доказательством без пиксельной проверки панели.

## Что это меняет в бэклоге

| Было (консилиум) | Стало |
|---|---|
| P0-A подтверждение действий | снято решением владельца; риск записан |
| P0-E экран утверждения критерия | снято; вместо него baseline/verdict |
| P0-F тавтология verify | закрыто baseline + `baselineMatched` + `lastObserved/lastReason` |
| P0-H read_page слепой, ref_N мёртв | закрыто: `ui_read_page` возвращает дерево, `ui_act { ref }` работает |
| P0-I гейты не падают | закрыто: `selftest` собирает, `live` падает на `STALE`, добавлен `check-engine` |
| P0-B/C/D жизненный цикл панели | реализовано в коде, требует живого подтверждения |

## Открытые риски, принятые осознанно

1. Страница может подсунуть модели инструкцию, а агент выполнит действие без подтверждения —
   границы: только http(s), приватные адреса запрещены, действия лимитированы, действия
   видны в `lastAct`/логах.
2. `verified` опирается на замер внутри страницы: страница может подменить DOM-API.
   Митигация в бэклоге: сравнение с внешним baseline (скриншот до/после) — не реализовано.
3. Зависимость от приватных API ядра (`ctx.get('sidebarRight')`, `registerCloseHandler`,
   `keepMounted`): при обновлении DSH возможна деградация; проверка версии не сделана.

## Уроки (learning log)

1. **Офлайн-гейт без сборки — ложнозелёный.** `npm run selftest` теперь собирает перед проверками.
2. **Живой гейт без падения — тоже ложнозелёный.** `npm run live` возвращает код 1 на `STALE`.
3. **Отсутствие экспорта не видно сборщику.** Введён `check-client-imports.mjs`; панельный
   краш `showSession is not defined` больше не должен доходить до живой панели.
4. **«Проверено по `/health`» ≠ «проверено в панели».** Пиксельная проверка панели — отдельный
   обязательный пункт живой приёмки, а не следствие зелёного `/health`.
5. **Одна правка — один класс ошибок.** Изменения импортов/жизненного цикла делаются вместе
   с guard'ом, который ловит именно этот класс.
